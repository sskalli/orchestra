# Technical design

Orchestra runs a local TypeScript server and a React browser UI. The server owns configured repositories, session identities, queues, each task's record of its worktrees and Git activity, and persistent task data. Codex App Server executes turns and owns its native child threads. A Claude engine presents Claude Agent SDK sessions through the same App Server protocol subset. A thread is one Claude Code session, and a turn is one query over streamed input that also carries steering messages. Orchestra's workspace tools are an in-process MCP server. Claude permission prompts become the same approval requests. Subagent tasks become native child threads. A local journal records thread and turn outcomes for restart recovery.

## Sessions

A direct task maps to one addressable Codex thread. A repository task's turns use a workspace-write sandbox whose writable roots are the selected checkouts, their shared Git directories, the tool caches in the home folder (such as `~/.npm` and `~/.cache`), and any folders the user allowed for the task. Network access is on, because Codex's sandbox can only allow all hosts or none. A general chat stays read-only and offline. When another task is running a turn in the same repository, the new turn gets a chat warning and context asking the agent to stay in its own worktree. Native child records track provider thread IDs, parent relationships, activity, replies, and observed usage. Child chats are inspected by ID and the parent coordinates their work.

Each user message records the provider turn it started. Editing one calls `thread/revert` with that turn as `beforeTurnId`, which drops the turn and every later one from the thread history. If that succeeds, Orchestra removes the message and everything after it from the saved transcript, reopens questions whose answers were removed, and sends the edited text as a new turn. A failed revert changes nothing. The Claude engine names each turn after its prompt's session UUID. It records the session entry before that prompt, and the next query resumes there with `resumeSessionAt`. Rewinding to the first prompt starts a new Claude Code session. Native child records from removed turns stay on the map. Files are not reverted.

Every task turn uses on-request approvals, so the agent can ask for access the sandbox does not grant. Orchestra shows each native Codex request in the task chat: a command outside the sandbox, a file change outside the writable roots, or a permission request for extra paths or network. The card shows the exact command, files, paths, and working directory. It offers only the choices Codex lists for that request. If Codex offers cancel but not decline, the card warns that declining stops the turn. Each card is bound to its live provider request, and Orchestra relays exactly one decision. A pending approval expires when the provider resolves the request, the turn ends, or Orchestra restarts. Orchestra declines a request it cannot display in full, such as unlisted files or hidden characters. A request from a native child appears on its task's card and names the child, while the task's turn runs; after that turn it is declined with a note in the child's chat. A child's finished command also triggers the task's Git check. Allow for this task also lists the folders later turns may write: requested write paths, or the folders of edited files, never the home folder or the filesystem root from a single file. Only the folders listed on the card are granted.

On the Claude engine, a repository task's sandboxed shell commands run without asking, including the ones Claude Code cannot analyse in advance (variables, loops, substitutions, inline scripts). The sandbox still limits them to the task's writable folders, the tool caches in the home folder (such as `~/.npm` and `~/.cache`), and the hosts the task may reach: its repositories' Git remotes and the npm and Yarn registries. A command that asks to leave the sandbox, a new host, a web fetch and anything in a general chat still ask. Requests from background agents reach the task's own card and name the agent, except network requests, which Claude Code does not attribute. Each card states in plain words why it asks, and shows the folder the command actually runs in, which Claude Code's tool hooks report. A finished shell command also triggers Orchestra's Git check, so commits, branches and worktrees appear during long turns, not only when the turn ends. A command Claude Code was configured to exclude from the sandbox (`sandbox.excludedCommands` in the user's settings) is not detected and also runs without asking.

Product questions bind a pending decision to its task and message. An accepted answer is persisted with the continuation. Interrupted and uncertain provider turns are reconciled without blindly resending input.

## Git activity

Orchestra reads each selected repository's branch and remote-tracking tips and its worktrees at turn start, shortly after commands finish, and at turn end. Readings run asynchronously, one at a time per task. Git's reflog says why each ref moved: commits, merges and rebases are reported, as are pushes ("update by push"), while pulls, fetches and resets are not. A linked worktree belongs to the first task that sees it appear while no other task works in that repository, and a branch belongs to the task that owns the worktree it is checked out in. A branch in the local checkout belongs to the running task only when no other task works in that repository. Activity Orchestra cannot attribute is left out.

On a task's first turn Orchestra snapshots each local checkout's tracked contents, uncommitted edits included, with `git stash create`, and keeps the commit under `refs/orchestra/task-start/<task>`. The changes view diffs the checkout against it, and each task worktree against the commit it forked from. Deleting the task removes the ref. Tasks saved by versions with approved implementation turns keep their worktrees and checkout edits as review locations.

## Local state

Persist direct task history and enough queue and thread information to resume after restart. Files dropped on a composer are uploaded to the local server, stored privately in their own folder under the workspace state's attachments directory, and inserted into the draft as absolute paths; they are never served back. Codex sandboxes already read them, and the Claude engine lets read-only tools open them without a prompt. Track model settings and usage separately from workspace state. Browser preferences hold drafts and camera positions. Isolate live workspaces by their repository identity and Codex provider.
